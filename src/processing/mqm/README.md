# Локальный MQM-анализ фрагментов

Пайплайн: SimAlign → COMETKiwi → кандидаты → корпус → MQM. Локальная
instruction-модель предлагает ошибки и наблюдения без эталонного перевода.
Это GEMBA-MQM-подобная методика, а не поставляемый checkpoint оригинального GEMBA.
Правильный формат и реальные цитаты не доказывают правильность смыслового вывода:
замечания имеют `status: needs_review`, `semantic_validation: model_only`.

## Запуск

Запустите OpenAI-совместимый сервер LM Studio, Ollama или llama.cpp, загрузите
мультиязычную instruction-модель и укажите точное имя из `/v1/models` на странице MQM.
Python-библиотека модели и COMET в окружении приложения для этого этапа не нужны.

```powershell
python -m src.processing.main --stage mqm
python src/processing/main.py --stage mqm
```

Тот же этап доступен отдельной кнопкой и включён в полный пайплайн. Для независимых
файлов, без реестра произведений приложения:

```powershell
python -m src.processing.mqm.io --candidates data/review_candidates/book.candidates.json --corpus data/corpus/book.json --output data/mqm_reports/book.mqm.json --model YOUR_MODEL --base-url http://127.0.0.1:1234/v1 --scope candidates
```

`--corpus` необязателен для независимого CLI. Проектный этап требует корпус версии 2
и проверяет совместимость документов, групп и токенных связей с кандидатами.
Область `all` проверяет окна всех якорей; `candidates` — отобранных кандидатов.

Пример `data/mqm_settings.json`:

```json
{
  "base_url": "http://localhost:1235/v1",
  "model": "qwen2.5-7b-instruct-1m",
  "revision": "Q4_K_M",
  "scope": "candidates",
  "timeout": 120,
  "max_tokens": 2048,
  "json_mode": true,
  "resume": true,
  "include_word_links": false,
  "max_retries": 0,
  "max_fragments": 8,
  "min_priority": 0
}
```

`max_tokens` ограничивает ответ, а не вход. Размер окна COMET также не является
лимитом полного запроса MQM. Контекст сервера должен вмещать инструкции, тексты,
подсказки и ответ; универсального API для проверки его токенизатором нет.
Ключ авторизации при необходимости берётся из `MQM_API_KEY`, не из URL.
Он не сохраняется в отчётах. При явном отказе сервера от `response_format/json_object`
есть одна попытка без этого необязательного параметра; ответ всё равно проверяется.

## Один фрагмент — все его кандидаты

Общий сборщик `analysis/fragments.py` используется кандидатами, MQM и интерфейсом.
Идентичность окна определяется индексами всех предложений обеих сторон.
Одинаковые окна имеют один `fragment_id`, список `anchor_group_indices` и все
сигналы кандидатов, попавших в окно. Приоритет очереди не суммируется повторно
из-за нескольких якорей. `max_fragments` применяется после объединения окон.

Разные пересекающиеся окна автоматически не сливаются: у них другой контекст
и ограничения COMET. Точные повторные замечания между ними учитываются один раз
по категории и координатам в корпусе. Разные координаты не склеиваются эвристически.
COMET также вычисляет оценку одинаковых входных пар один раз, сохраняя результаты
для всех исходных якорей.

Центральная группа — только навигационный якорь. Проверяется весь фрагмент;
порядок предложений в переводе может отличаться. Группы Vecalign и связи слов —
гипотезы, а не доказанные соответствия.

## Компактный запрос v5

`source` явно обозначен как оригинал (`role: original`), `target` — как перевод
(`role: translation`), с языком каждой стороны. Текст каждого предложения
передаётся один раз с обозначением `S201` / `T198`. Группы выравнивания содержат
только ссылки на предложения. Сигналы объединяются по коду и ссылкам.

Опция `include_word_links` передаёт до 48 компактных соответствий вокруг токенов,
отмеченных лексическими сигналами, без полных таблиц токенов и документных координат.
Это подсказки для проверки, не критерий правильности перевода. Модель должна
искать смысл во всём окне, учитывать перефразирование, не проверять историческую
истинность оригинала и не заполнять квоту замечаний. Инструкция ограничивает
ответ шестью ошибками и двумя короткими наблюдениями.

Ответ модели:

```json
{
  "findings": [{
    "category": "Accuracy/Mistranslation",
    "severity": "major",
    "explanation": "Изменено заболевание.",
    "source_spans": [{"ref": "S201", "quote": "саркома"}],
    "target_spans": [{"ref": "T198", "quote": "heart attack"}]
  }],
  "observations": []
}
```

Категории: Accuracy/Mistranslation, Accuracy/Omission, Accuracy/Addition,
Terminology, Fluency/Grammar, Fluency/Spelling, Style/Register. Наблюдения:
uncertain, alignment_issue, acceptable_variation; они не начисляют штраф.
Модель копирует цитаты, программа вычисляет координаты. Ссылка неправильной
стороны отклоняется. Неверный индекс восстанавливается только по единственному
дословному совпадению на нужной стороне текущего окна с отметкой в диагностике.
Неточные, придуманные или неоднозначные цитаты отклоняются. Старый формат
`sentence_index` поддерживается с той же проверкой.

## Отчёт версии 2 и относительные спаны

Основной файл: `data/mqm_reports/<пара>.mqm[.adaptive].json`.
Он содержит входные фрагменты и вердикты, метаданные модели/входов и сводные метрики.
Полные документы, токенные таблицы, списки попыток и отклонённые предложения модели
не копируются в основной отчёт.

Каждый элемент `fragments` содержит:

- `fragment_id`, якоря и группы исходного окна;
- `source.text`, `target.text` — предложения окна, соединённые переводом строки;
- `source.sentences`, `target.sentences` — ID/индексы предложений и их диапазоны
  внутри соответствующего текста фрагмента, без повторения текста;
- `findings`, `observations` с маркерами E1/E2/O1 и относительными спанами;
- статус, число отклонений, ошибку запроса при наличии, fingerprint для продолжения.

Сокращённый пример стороны и спана:

```json
{
  "source": {"text": "Саркома.", "sentences": [{"index": 201, "sentence_id": 201, "start": 0, "end": 8}]},
  "source_spans": [{"start": 0, "end": 7, "quote": "Саркома"}]
}
```

Все сохранённые спаны отсчитываются **от начала своей стороны фрагмента**,
в Unicode code points; `end` исключается. Всегда проверяется
`fragment[side].text[start:end] == quote`. Полные координаты для объединения
повторов и просмотра книги восстанавливаются через карту предложений и корпус.
Интерфейс получает готовые куски текста, поэтому отличие индексации JS/UTF-16
не сдвигает выделение эмодзи и других символов вне BMP.

Диагностика находится в соседнем `*.mqm[.adaptive].diagnostics.json`: попытки,
отклонения, точная причина `finish_reason`, доступные счётчики токенов и время.
Оба файла записываются атомарно после каждого окна. Неудачный ответ не считается
отсутствием ошибок. Статусы: completed, partial_invalid, failed, not_run_after_failure.
Сбой отдельного ответа не останавливает очередь; недоступность сервера/авторизация
останавливают оставшиеся запросы с сохранением частичного результата.

## Просмотр и продолжение

На странице MQM доступны «Фрагмент» и «Весь текст», список, предыдущий/следующий
фрагмент, список всех замечаний выбранного окна. Приглушённые отметки показывают
кандидатов и замечания; нажатие выбирает конкретный вердикт с маркером, категорией
и серьёзностью. Окна без результата обозначены как «вердикт отсутствует».
Выбор центрирует обе панели на соответствующем участке. Полный текст загружается
из корпуса/кандидатов только при совпадении SHA-256 и fingerprints; при отсутствии
этих файлов фрагменты основного отчёта остаются доступны автономно.

Старые отчёты версии 1 открываются без перезаписи, скачивание из интерфейса
экспортирует компактную версию 2. Продолжение повторно использует только completed
при совпадении значимых данных, модели/revision, prompt, scope и весов; цитаты
проверяются заново. Изменение только created_at или путей/форматирования входов
не требует новых запросов. Изменив веса модели под тем же именем, обновите revision.
`--no-resume` отключает продолжение; рост max_fragments добавляет новые окна.

Prompt v5 требует нового анализа старых MQM-ответов. Пересчитывать SimAlign,
COMET или корпус не нужно, если их данные совместимы и не менялись. Новая индексация
фрагментов появляется при повторном поиске кандидатов; старые кандидаты тоже
объединяются непосредственно при запуске MQM и открытии интерфейса.

## Метрики и качество

Метрики используют уникальные координаты корпуса для исключения точных повторов,
а охват — объединение предложений окон без двойного подсчёта. Вес minor=1,
major=5, critical=25 — проектная шкала, а не вероятность ошибки. Частоты приводятся
к 1000 слов оригинала; regex и знаменатели записаны в метаданных. Нулевой знаменатель
даёт null. Количество уникальных окон и якорей отражается отдельно.

При выборке кандидатов частота по всему документу является только наблюдаемым
числом предложений ошибок на полный объём, без экстраполяции. Даже completed
и полный охват означают технически проверенные ответы, а не подтверждение смысла
человеком. Тесты протокола и интерфейса не измеряют точность конкретной модели:
для неё нужна вручную размеченная выборка с ошибками и корректными адаптациями.
