# Text Pipeline · Workbench — Streamlit UI

Весь интерфейс размещён в `src/ui/`. Папки `src/processing/` и `src/external_tools/` не заменяются и не изменяются.

## Установка

1. Скопируйте папку `src/ui` в **корень вашего проекта** с сохранением структуры.
2. Из корневой папки проекта установите Streamlit:
   ```powershell
   python -m pip install -r src/ui/requirements-ui.txt
   ```
3. Запустите:
   ```powershell
   python -m streamlit run src/ui/app.py
   ```

Устанавливайте Streamlit в среду основного пайплайна. LASER и Vecalign могут использовать отдельные среды через уже существующий `ExternalToolsRunner`.

## Рабочее место

- Верхнее меню: **Файлы / Выравнивание / Настройки**.
- Две независимые панели просмотра TXT/CSV/JSON/JSONL и .align. Поиск файлов в `data/`, кроме `data/ui_jobs/`. CSV показан таблицей; JSON — деревом либо исходным текстом.
- Правая колонка: документы, размер группы Vecalign (2/3/4), отдельные этапы, общий запуск и остановка главного процесса.
- Внизу закреплена кнопка **Журнал выполнения**. При раскрытии отображает живой `stdout`/`stderr` фонового процесса с обновлением каждые 2 сек, без автоанимаций.
- В **Выравнивание** можно посмотреть таблицу оригинала/перевода с индексами, стоимостью Vecalign, фильтрами групп/пропусков, экспортом CSV.
- В **Настройки** можно импортировать текстовые файлы в `data/imported/`, а затем явно назначить TXT как исходник, если `data/raw/<name>.txt` ещё не существует.

## Документы (согласованы с ранее приведённым pipeline_main_example.py)

- `original-rus` (RU)
- `glenny-translation-en` (EN)
- `pevear-translation-en` (EN)

Ожидаемые исходники (UTF-8):

```text
data/raw/original-rus.txt
data/raw/glenny-translation-en.txt
data/raw/pevear-translation-en.txt
```

Если имена отличаются, измените словарь `DOCUMENTS` и константы `SOURCE`/`TARGETS` в `src/ui/config.py`.

## Стадии и точные зависимости

1. **Очистка**: `text_normalizer.clean_text` (из существующего корневого модуля). `data/raw/*.txt` → `data/cleaned/*.txt`.
2. **Сегментация**: `src.processing.text_segmenter.SentenceSegmenter`; `postprocessor.SentencePostprocessor`; для RU также `RuBoundaryClassifier`, `BoundaryAwareSegmenter`, `BoundaryDatasetBuilder` и модель `models/ru_boundary_rubert_v4/best_model`. → `data/segmented/*.json`.
3. **Нормализация и экспорт**: `normalizer.TextNormalizer`, `src.processing.text_json_txt_exporter.TextJsonTxtExporter`. → `data/normalized/*.json`, `data/overlaps/input/*.txt`.
4. **Группы предложений**: `ExternalToolsRunner.generate_overlaps`. → `data/overlaps/output/*.txt`.
5. **LASER**: `ExternalToolsRunner.generate_embeddings`. → `data/embeddings/*.emb`.
6. **Vecalign**: `ExternalToolsRunner.align` с `alignment_max_size` = выбранному значению. → `data/aligned/*.align`.
7. **Корпус**: `CorpusBuilder.build_corpus`. → `data/corpus/*.json`.

**Важно:** это UI-патч, а не самостоятельный архив полного пайплайна. Функциональные вызовы стадий 2–7 привязаны к сигнатурам из ранее обсуждавшегося `pipeline_main_example.py`. Если ваши текущие классы/импорты отличаются, адаптируйте только `src/ui/pipeline.py`. Интерфейс честно показывает ошибки отсутствующих модулей, он не подменяет их имитациями.

Общий запуск останавливается на первой ошибке. Отдельные этапы можно запускать при наличии результатов предшествующих стадий. Входы и результаты в основном формате **внутри проекта**, не подменяются содержимым окон просмотра. Просмотр файлов и выбор исходных документов для пайплайна — две разные операции.

## Ограничения

- Запуск локальный. **Не публикуйте** сервер в Интернет: у него есть доступ к локальным файлам и исполняемым модулям проекта.
- `data/` используется как рабочий каталог. Импорт файлов не перезаписывает исходники без явного назначения; назначение запрещает заменять уже существующий `data/raw/*.txt`.
- При отмене задачи завершается только Python-worker. Внешние процессы LASER/Vecalign, если они запущены дочерними и не завершаются автоматически, могут потребовать отдельного завершения.
- Журналы находятся в `data/ui_jobs/<id>.log`. Задания исполняются асинхронно; при перезапуске браузера можно просмотреть журнал последней задачи, но управление активной задачей зависит от текущей Streamlit-сессии.
- При выборе `max_size=4` убедитесь, что существующий `ExternalToolsRunner.generate_overlaps` действительно создает группы до 4 предложений; интерфейс не изменяет параметры генератора, пока его точная сигнатура не проверена.
- Таблица соответствий использует **нулевые индексы** Vecalign и содержимое `.txt` из `data/overlaps/input` без фильтрации пустых строк. Не изменяйте порядок строк после выравнивания.

## Проверки интерфейсного бэкенда


## Настройка LASER и Vecalign

По умолчанию инструменты запускаются напрямую в текущей ОС, с текущим Python.
Для отдельных окружений задайте `LASER_PYTHON` и `VECALIGN_PYTHON` — пути к их
интерпретаторам. Для исходного checkout Vecalign задайте `VECALIGN_SCRIPT`
(путь к `vecalign.py`) и `VECALIGN_OVERLAP_SCRIPT` (путь к `overlap.py`). Если
они не заданы, используется прежний модульный интерфейс `vecalign.vecalign`
и `vecalign.overlap`; он должен быть доступен выбранному Python.

Для запуска из Windows через WSL явно задайте `EXTERNAL_TOOLS_BACKEND=wsl`
и `WSL_PROJECT_DIR` — Linux-путь к этому проекту. Пути к Python и скриптам
в этом режиме также должны быть путями внутри WSL. При необходимости имя
команды WSL задаётся в `WSL_EXECUTABLE` (по умолчанию `wsl.exe`). В режиме
`native` WSL не используется. Аргументы с пробелами передаются без потерь.

Модели spaCy, локальный checkpoint RuBERT, LASER и Vecalign устанавливаются
отдельно. Интерфейс не имитирует отсутствующие этапы.

Корпус и таблица выравниваний используют общий строгий парсер: каждое
предложение должно встретиться ровно один раз, в исходном порядке. Пропуск
перевода записывается строкой с пустой одной стороной; две пустые стороны
недопустимы. Неполный или повреждённый `.align` не принимается.

Панели просмотра подстраиваются под высоту окна и раскрытый журнал. Состояние
задачи обновляется автоматически: после успешного или ошибочного завершения
worker кнопки других этапов снова доступны без остановки вручную.
