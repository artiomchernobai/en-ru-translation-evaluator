# Поиск кандидатов на проверку перевода

Модуль собирает проверяемые основания, а не окончательные MQM-ошибки.
Его можно запустить без моделей, доступа к сети, новых зависимостей и обучения.
В этом PR смысловой анализ локальной LLM сознательно отложен по запросу пользователя.

## Входы и совместимость

Для каждой пары произведение/перевод используются два результата пайплайна:

1. `data/word_alignment/<пара>.json`: нормализованные тексты, предложения,
   глобальные ID токенов, координаты, группы Vecalign, методы и связи SimAlign.
2. `data/translation_quality/<пара>.cometkiwi.json`: состав соседних окон,
   точные строки Vecalign и оценки окон.

Перед объединением проверяются пара документов, количество и порядок групп,
полное покрытие предложений, стоимости и исходные строки Vecalign, тексты окон,
идентификаторы предложений, координаты и принадлежность токенов. Когда оба файла
содержат SHA-256 исходных входов, они также должны совпасть. Несовместимые результаты
не смешиваются: нужно повторить соответствующий этап на одном наборе данных.

Ядро `collect_candidates(words, comet, ...)` работает с объектами, не знает имён
произведений или файлов и не изменяет входы. Имена и сохранение реализованы снаружи.
Старые результаты не удаляются, при ошибке входов существующий отчёт сохраняется.

## Правила и их ограничения

| Код сигнала | Основание | Вес приоритета |
|---|---|---:|
| `sentence_gap` | Пустая сторона центральной записи Vecalign | 40 |
| `high_vecalign_cost` | Стоимость выше P90 непустых групп этой пары | 20 |
| `low_comet_window` | Оценка всего окна ниже P10 оценённых окон этой пары | 20 |
| `comet_unscored` | Окно не оценено: пустая сторона или ограничение длины | 10 |
| `quantity_mismatch` | Различаются распознанные числа, века или величины | 35 |
| `terminology_mismatch` | Различаются понятия настраиваемого двуязычного словаря | 40 |
| `negation_mismatch` | Явное отрицание найдено только с одной стороны | 15 |
| `unlinked_content` | Непунктуационные токены без связей выбранного метода SimAlign, за исключением краткого списка служебных слов | 10 |
| `word_alignment_unavailable` | SimAlign не вычислен для группы | 5 |

Вес — инженерный приоритет ручной проверки, **не вероятность ошибки и не MQM
severity**. Веса суммируются до 100. Правила одной группы объединяются в одного
кандидата. Группы сортируются по приоритету. При равных значениях сортировка
стабильна по позиции текста. Квантили вычисляются как элемент отсортированного
массива с индексом floor(q*(n-1)); строгие сравнения не создают флаги на всех
группах при одинаковых оценках. Нули стоимости пропусков исключаются из P90.
Отсутствующая оценка COMET не заменяется нулём.

Правила ориентированы на RU → EN. Сравниваются цифровые числа, часть написаний
веков (1–12, 20, 21), цифровые века, единицы м/см/км и г/кг с переводом к общей
величине. Например, 1000 м и 1 km равны. Это не полный парсер дат, числительных,
денег или всех систем единиц; десятичная запятая считается десятичным разделителем,
поэтому запись тысяч через запятую требует проверки.

Встроенный демонстрационный словарь содержит только «саркома лёгкого» и «инфаркт /
сердечный приступ». Он показывает независимость терминологических сигналов от
оценки COMET и наличия связей SimAlign. Он не является медицинской онтологией.
Имена, другие заболевания и предметы добавляются в двуязычный словарь проекта.
Общий NER, смысловые роли участников, действия и произвольные перефразирования
пока не распознаются: это задача следующего этапа с локальной моделью.

Отрицания и несвязанные токены также не доказывают ошибку: возможны идиомы,
перестройка фразы, погрешности SimAlign и сдвиги границ. Все основания сохраняются
для проверки с соседним контекстом. Не следует выдавать долю кандидатов за долю
неправильного перевода.

## Локализация и формат JSON

Отчёт сохраняется в `data/review_candidates/<пара>.candidates.json`:

- `source`, `target`: нормализованные документы с таблицами предложений и токенов;
- `candidates`: группа, приоритет, состояние `needs_review`, список независимых
  сигналов, их объяснения, точные цитаты и диапазоны обеих сторон;
- каждый диапазон: `sentence_index`, исходный `sentence_id`, `start`, `end`,
  `quote`, `document_start`, `document_end`, `token_ids`;
- `semantic_tasks`: подготовленные данные **для всех групп**, включая группы без
  сигналов и с высокой COMET-оценкой: центр и соседние записи Vecalign, их тексты,
  оценки, ссылки на кандидатов и связи выбранного метода SimAlign;
- `configuration`: пороги, квантили и словарь, использованные в этом запуске;
- `inputs`: SHA-256 двух входных файлов; `created_at`, версия анализа и сводка.

Координаты: Unicode code points, начало включается, конец исключается. Смещения
документа относятся к нормализованным предложениям, соединённым `\n`, а не к
исходному TXT. У повторяющихся слов сохраняются отдельные позиции; поиск первого
совпадения цитаты не используется. Пустая сторона имеет пустой список диапазонов.

`semantic_analysis: not_run`, `semantic_tasks[].status: not_analyzed` и
`semantic_groups_checked: 0` прямо обозначают отсутствие смысловой проверки.
Поэтому отсутствие кандидата не выдаётся за подтверждение качества перевода.

Подготовленные задачи позволят позднее запускать локальный MQM-анализ всех групп
либо приоритетную очередь. Его результаты должны будут проходить независимую
проверку цитат/диапазонов и дедупликацию по положениям, а не только тексту цитаты.
Это следующий PR; клиент LLM, вызовы модели и окончательный MQM-отчёт здесь отсутствуют.

## Запуск

```powershell
python -m src.processing.main --stage candidates
python src/processing/main.py --stage candidates
```

Этап также включён в полный пайплайн после SimAlign и COMETKiwi. В интерфейсе
есть кнопка этапа и страница «Кандидаты»: фильтрация по сигналам, приоритет,
подсветка точных фрагментов оригинала и перевода, контекст, координаты/ID токенов,
строки Vecalign и скачивание JSON. HTML из книг экранируется.

Для произвольных пар:

```powershell
python -m src.processing.analysis.io --words data/word_alignment/book.json --comet data/translation_quality/book.cometkiwi.json --output data/review_candidates/book.candidates.json
```

Настройки приложения: необязательный файл `data/candidate_settings.json`.
Для произвольного CLI можно передать тот же JSON через `--settings <путь>`.
Пример (добавляет словарь вместо встроенного, регулярные выражения без учёта регистра):

```json
{
  "low_quantile": 0.1,
  "high_quantile": 0.9,
  "glossary": [
    {"id": "Berlioz", "source": "Берлиоз\\w*", "target": "Berlioz"},
    {"id": "lung_sarcoma", "source": "сарком\\w*\\s+л[её]гк\\w*", "target": "(?:lung|pulmonary)\\s+sarcoma"}
  ]
}
```

## Как проверять результат

Сначала просмотреть известные смысловые подмены, реальные пропуски и ошибки границ.
Отдельно взять случайные группы без сигналов: так оцениваются пропуски детектора.
Разметить причину и полезность каждого сигнала; лишь затем подбирать пороги и веса.
Тесты программной корректности не являются измерением качества обнаружения ошибок
на литературном корпусе.
