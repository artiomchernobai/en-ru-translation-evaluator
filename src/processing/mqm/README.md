# Локальный GEMBA-MQM-подобный анализ

Этап завершает пайплайн: кандидаты → локальная instruction-модель → отчёты по
фрагментам → сводные JSON-метрики. Это оценивание без эталонного перевода.
GEMBA-MQM здесь означает методику LLM-оценивания по MQM-рубрике, а не отдельный
поставляемый checkpoint оригинального GEMBA. Модель выбирает пользователь.

## Быстрый запуск

1. Запустите локальный OpenAI-совместимый сервер и загрузите подходящую
   мультиязычную instruction-модель (RU/EN). Поддерживаются LM Studio, Ollama,
   llama.cpp с совместимым `/v1/chat/completions`. Python-библиотека модели
   в окружении приложения не требуется; зависимостей COMET в этом этапе нет.
2. Примеры адресов: LM Studio `http://127.0.0.1:1234/v1`, Ollama
   `http://127.0.0.1:11434/v1`. Включите API сервера. Используйте точное имя модели,
   которое возвращает его `/v1/models` или показывает интерфейс сервера.
3. На странице **MQM → Локальная модель и параметры** сохраните адрес, имя,
   версию/квантизацию модели и область анализа. По умолчанию проверяются кандидаты;
   можно выбрать все группы текста.
4. Запустите **MQM — анализ локальной моделью**. Тот же этап включён последним в
   полный пайплайн. Если модель не настроена, этап завершится понятной ошибкой,
   а не выдаст пустой отчёт за успешную оценку.

```powershell
python -m src.processing.main --stage mqm
python src/processing/main.py --stage mqm
```

Для произвольных имён произведений, без реестра документов приложения:

```powershell
python -m src.processing.mqm.io --candidates data/review_candidates/book.candidates.json --output data/mqm_reports/book.mqm.json --model YOUR_LOADED_MODEL --base-url http://127.0.0.1:1234/v1 --scope candidates
```

Для полной проверки замените `--scope candidates` на `--scope all`.
Настройки приложения находятся в `data/mqm_settings.json`, например:

```json
{
  "base_url": "http://127.0.0.1:1234/v1",
  "model": "YOUR_LOADED_MODEL",
  "revision": "local-checkpoint-and-quantization-version",
  "scope": "candidates",
  "timeout": 120,
  "max_tokens": 2048,
  "json_mode": true,
  "resume": true
}
```

`max_tokens` ограничивает **ответ**, а не вход. Контекст локальной модели может
содержать заметно больше токенов, чем окно COMET: туда добавлены рубрика, цитаты и
связи слов. Настройте достаточный контекст в самом сервере (например, начните с
16K, если модель/память позволяют). Совместимый API не предоставляет универсального
способа проверить вход его токенизатором: автоматическое обрезание входа на сервере
следует отключить или контролировать. Рост контекста и GPU не гарантируют точность.
Если сервер не поддерживает `response_format: json_object`, снимите соответствующий
флажок; JSON-контракт ответа всё равно проверяется. Обрезанные ответы с finish_reason
`length` не считаются успешными, их можно повторить с большим лимитом ответа.

При необходимости авторизации ключ берётся из `MQM_API_KEY`. Он не записывается
в настройки, запросные fingerprints, журнал или отчёт. Встроенные credentials в URL
не допускаются. По умолчанию используется localhost; другие адреса нужно указать явно.

## Что получает модель

Каждый запрос содержит центральную группу, фактический фиксированный/адаптивный
контекст кандидата, тексты и ID предложений, токены и связи SimAlign, сигналы
эвристик. Приоритет очереди не превращается в severity. Все группы в режиме `all`
имеют те же контексты, даже если эвристики не нашли кандидата.

Версионированный prompt в `prompt.py` задаёт GEMBA-MQM-подобную рубрику:
проверить факты, участников, действия, числа, отрицания, термины, пропуски,
добавления, грамматику и регистр; отличать ошибку от естественного перефразирования.
Книжный текст объявлен данными, его инструкции не должны исполняться.

Модель возвращает JSON с двумя массивами:

- `findings`: Accuracy/Mistranslation, Accuracy/Omission, Accuracy/Addition,
  Terminology, Fluency/Grammar, Fluency/Spelling или Style/Register;
  предполагаемая серьёзность minor/major/critical, объяснение, цитаты, необязательное
  предложение исправления;
- `observations`: acceptable_variation (допустимая адаптация), uncertain
  (сомнительное место), alignment_issue (проблема входа/выравнивания).
  Эти наблюдения не начисляют штраф за ошибку.

Нулевой список ошибок допустим. Модель не должна выдумывать «идеальный» перевод
или штрафовать за собственные стилистические предпочтения.

## Проверка цитат и локализация

Каждая цитата содержит `sentence_index`, `quote` и необязательные `start/end` внутри
предложения (Unicode code points, конец исключается). Программа проверяет:

- предложение входит в переданный контекст;
- цитата буквально присутствует в предложении; если она повторяется, нужны точные
  смещения, выбор первого совпадения запрещён;
- хотя бы одна сторона замечания затрагивает центральную группу;
- категория/серьёзность входят в допустимые значения;
- для подмены смысла/терминологии нужны цитаты с обеих сторон; у пропуска может
  отсутствовать цитата перевода, у добавления — цитата оригинала.

После проверки добавляются sentence ID, координаты документа и token IDs из
предыдущего этапа. Неверные цитаты сохраняются в `rejected`, исключаются из метрик
и делают фрагмент `partial_invalid`. Совпадение цитаты доказывает только корректность
привязки: смысловой вердикт всё ещё может быть ошибкой модели. Его статус —
`needs_review`, semantic_validation — `model_only`.

## JSON и метрики

Результат на пару: `data/mqm_reports/<пара>.mqm.json` или
`<пара>.mqm.adaptive.json`. Поля отчёта:

- модель, версия prompt, конфигурация контекста и scope;
- SHA-256 входного отчёта кандидатов и fingerprint запуска;
- `fragments`: статус, центральные предложения, контекст, исходная оценка COMET,
  замечания/наблюдения/отклонённые цитаты и метрики фрагмента;
- `findings`: уникальные замечания по всему запуску;
- `observations`: отдельные уникальные наблюдения;
- `metrics`: охват, категории, серьёзность, частоты и штрафные баллы.

Повторы с одной категорией и **точно теми же координатами** двух сторон учитываются
один раз; сохраняются все группы-источники и максимальная предложенная серьёзность.
Перекрывающиеся, но разные по координатам замечания автоматически не склеиваются:
это могло бы удалить разные ошибки. Допустимые варианты также дедуплицируются.

Основные показатели:

```text
наблюдаемая частота по документу = 1000 × уникальные замечания / слова всего оригинала
частота в проверенных центрах   = 1000 × уникальные замечания / слова проверенных центров
штрафные баллы                  = Σ весов серьёзности уникальных замечаний
среднее число на группу         = уникальные замечания / число проанализированных групп
```

Вес minor=1, major=5, critical=25. Это явно заданная проектная шкала, а не обученная
вероятность и не доказанная «доля отклонения от идеала». Ядро принимает другую шкалу
через параметр `weights`; фактические веса записываются в JSON. Частоты приводятся
к 1000 слов русского оригинала. Слово определяется regex, записанным в метаданных;
числа считаются словами, пунктуация не считается. Нулевой знаменатель даёт null.

Охват считается по **центральным** предложениям, без многократного подсчёта соседей.
Есть количество запрошенных/проанализированных/полностью завершённых групп и доля
слов оригинала, попавших в центры. Частично валидные ответы отдельно отмечаются.
При анализе только кандидатов частота по всему документу — наблюдаемые предложения
ошибок на полный объём, без экстраполяции на непроверенный текст. При полном режиме
охват признаётся полным только после успешных валидных ответов для каждой группы.
Даже при полном охвате это автоматические замечания, не человеческий золотой стандарт.

Отчёт не выдаёт проценты «идеальности», вероятности правильности или человечески
подтверждённое число ошибок. Категории, наблюдения, веса и охват позволяют строить
последующий MQM-отчёт после ручной проверки.

## Сбои и продолжение

JSON атомарно обновляется после каждого фрагмента. Некорректный или обрезанный
ответ получает ограниченную повторную попытку; при неудаче фрагмент отмечается
`failed`, и очередь продолжается. При недоступности сервера, ошибке авторизации
или конфигурации остальные фрагменты получают `not_run_after_failure`. Частичный
отчёт остаётся доступен и не выдаётся за успешный результат.

Повторный запуск переиспользует только завершённые фрагменты при совпадении входа,
модели/версии, prompt, scope и весов; цитаты кэша также перепроверяются. Неудачные и
частично валидные фрагменты оцениваются заново. Изменив локальные веса модели под
тем же именем, обновите `revision` или отключите resume. JSON CLI поддерживает
`--no-resume`. Успешное переиспользование не требует новых запросов к серверу.

## Проверка качества

Тесты проверяют протокол, цитаты, агрегирование и обработку сбоев. Они не доказывают
качество конкретной локальной модели. Начните с небольшой ручной выборки, включающей
известные подмены смысла и корректные литературные адаптации. Сравнивайте ложные
обвинения, пропущенные ошибки и согласованность severity; лишь затем анализируйте
целые произведения. Запуск модели и её GPU/квантизация настраиваются в локальном сервере.

## Уточнение обработки локальных ответов (prompt v2)

Запрос теперь группирует исходный текст и перевод по Vecalign с явным
`is_center`; соседи служат только контекстом. Пустая сторона не заменяется текстом
соседней группы. Таблица токенов и связи передаются компактно, без повторения всего
окна и координат в нескольких структурах, чтобы уменьшить размер запроса.

После неверного JSON или отклонённых цитат допускается одна исправляющая попытка
(настройка `max_retries`, от 0 до 2). Модель получает причины отклонения и должна
вернуть полный заменяющий JSON. Каждый ответ проходит прежнюю строгую проверку;
ошибки соседей не переносятся на центр. В `attempts` сохраняется история отклонений.
Если исправление не удалось, результат остаётся partial_invalid/failed, а неверные
замечания не включаются в метрики. Для старых успешных ответов требуется повторный
анализ из-за смены версии prompt.

Некорректный ответ, его обрезание или индивидуальное превышение контекста не
прерывают всю очередь. Сбой соединения, авторизации и конфигурации останавливает
запуск. HTTP-ошибки теперь содержат сообщение сервера в JSON и журнале; известный
API-ключ скрывается. При явном HTTP 400 о неподдерживаемом response_format/json_object
производится одна попытка без этого необязательного параметра. Содержимое ответа
всё равно обязано быть валидным JSON.

Эти изменения повышают диагностируемость и устойчивость формата. Они не доказывают
точность смысловых вердиктов конкретной 7B-модели и не заменяют ручную калибровку.
