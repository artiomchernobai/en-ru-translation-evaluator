# Text Pipeline · Workbench

Запускайте из корня проекта:

```powershell
python -m pip install -r src/ui/requirements-ui.txt
python -m streamlit run src/ui/app.py
```

Верхнее меню: **Файлы / Проверка / Выравнивание / Настройки**.
Панель справа запускает этапы, нижний журнал показывает stdout/stderr.
При завершении worker кнопки автоматически становятся доступны. Настройки
и журнал не перекрывают рабочую область текста; панели меняют высоту вместе
с окном. Локальный сервер имеет доступ к файлам проекта, поэтому не выставляйте
его в публичный Интернет.

## Страницы

- **Файлы**: две компактные панели TXT, CSV, JSON/JSONL и `.align`. Выбор файла
  расположен прямо над текстом; сведения и скачивание убраны в раскрываемое меню.
  CSV показывает до 500 строк, текст — до 200 000 символов; скачивается весь файл.
- **Проверка**: просмотр связей слов из JSON SimAlign (описание ниже).
- **Выравнивание**: таблица групп Vecalign, фильтры пропусков/групп и экспорт CSV.
- **Настройки**: импорт файлов, явное назначение TXT исходному документу,
  диагностика доступных модулей. Существующие исходники не перезаписываются.

## Пайплайн и организация кода

Этапы: очистка → сегментация → нормализация/экспорт → overlaps → LASER →
Vecalign → SimAlign → корпус. Можно запустить отдельный этап при наличии входов.
Структура модулей обработки и актуальные импорты: [processing/README.md](../processing/README.md).

Интерфейс разделён на `views/`, общие `components/` и независимую загрузку/
валидацию данных `review_model.py`. `app.py` задаёт навигацию и компоновку;
`pipeline.py` связывает кнопки с обработкой, `jobs.py` и `worker.py` исполняют задания.

## Внешние инструменты

По умолчанию LASER/Vecalign запускаются в текущей ОС. Интерпретаторы задаются
в `LASER_PYTHON`, `VECALIGN_PYTHON`; пути к исходным скриптам Vecalign — в
`VECALIGN_SCRIPT`, `VECALIGN_OVERLAP_SCRIPT`. Без путей используется модульный
интерфейс `vecalign.vecalign` и `vecalign.overlap`.

Для WSL задайте `EXTERNAL_TOOLS_BACKEND=wsl`, `WSL_PROJECT_DIR` и пути к
интерпретаторам/скриптам внутри WSL. `WSL_EXECUTABLE` по умолчанию — `wsl.exe`.
LASER вызывается через `-m src.processing.alignment.embeddings` из корня проекта.
Модели spaCy, RuBERT и внешние окружения устанавливаются отдельно.

Поле «Размер группы Vecalign» ограничивает сумму сегментов обеих сторон:
3 разрешает 1:2 и 2:1, 4 — также 1:3, 3:1 и 2:2. Это значение используется
и при подготовке overlaps. При увеличении размера подготовьте overlaps и
эмбеддинги заново.

Поле «Штраф пропуска Vecalign (перцентиль)» передаёт `--del_percentile_frac`.
По умолчанию `0.20`, диапазон `0…1`; меньшее значение делает пропуски дешевле,
но может добавлять ложные. Для изменения только штрафа достаточно повторить
выравнивание. Параметры сохраняются в JSON задания и журнале.

SimAlign работает в окружении worker, независимо от окружения LASER.
Команды установки, API и формат результата: [alignment/README.md](../processing/alignment/README.md).

## Экран «Проверка»

Выберите JSON из `data/word_alignment/`, метод (`itermax`, `inter`, `mwmf`) и
область просмотра: весь текст или отдельный фрагмент Vecalign. Номер фрагмента
позволяет перейти к нему в обеих панелях. Нажатие на слово в любой панели
выделяет выбранный токен жёлтым, связанные слова другого текста — голубым.
Токены без связей выделены оранжевым. Серое пунктирное подчёркивание означает,
что блок не обработан моделью. Это не MQM-разметка ошибок перевода.

Если `data/raw/<document_id>.txt` соответствует токенам сохранённого JSON,
показывается исходный текст с абзацами и исходным оформлением. Сопоставляются
все токены по порядку с учётом форм кавычек и удалённых числовых ссылок;
нечёткое угадывание позиций не используется. При несовпадении или отсутствии
исходника показывается нормализованный текст, и источник отображения подписан.
Смещения Unicode корректно преобразуются для браузера, в том числе для эмодзи.

Просмотр не запускает модели. Смена метода использует сохранённые связи; если
их в файле нет, экран сообщает об этом. Текст передаётся компоненту как данные
и выводится текстовыми узлами, без исполнения HTML из произведения.


## Проверки

```powershell
python -m pytest tests src/ui/tests -q
```

Браузерный тест требует Playwright и Chromium. Он запускает отдельный временный
проект и сервер, не меняя пользовательские данные:

```powershell
$env:RUN_BROWSER_TESTS = "1"
python -m pytest tests/browser -q
```

При необходимости задайте `CHROMIUM_PATH` — путь к установленному Chromium;
иначе используется `chromium` из PATH либо браузер Playwright.
