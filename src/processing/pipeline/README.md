# Общие настройки и запуск

CLI и интерфейс используют `pipeline.runner.run_stage` и одни сохранённые параметры.
Страница «Настройки» содержит разделы общих параметров, сегментации, выравнивания
слов, кандидатов, COMETKiwi и MQM. На страницах просмотра остаются фильтры и кнопки
запуска; настройки моделей больше не дублируются там.

`data/pipeline_settings.json` хранит документы, Vecalign, RuBERT, SimAlign и окружения внешних инструментов.
Совместимые файлы `cometkiwi_settings.json`, `candidate_settings.json`,
`mqm_settings.json` продолжают использоваться для соответствующих этапов как
из CLI, так и из UI. Контекст кандидатов согласуется с сохранённым контекстом COMET.

По умолчанию Vecalign использует суммарный размер N+M=4 (включая 2:2 и 1:3),
перцентиль удаления 0.1. Это параметр стоимости пропуска, не порог вероятности.

```powershell
python -m src.processing.main --stage all
python -m src.processing.main --stage align
python -m src.processing.main --stage word_align
python -m src.processing.main --stage align --max-size 4 --deletion-percentile 0.1
python -m src.processing.main --root D:\piton --stage mqm --candidate-group 67 --target glenny-translation-en
```

Доступны все имена этапов из реестра. `--documents` задаёт список документов,
CLI overrides действуют на текущий запуск и не переписывают сохранённые настройки.
Дублирующий полный CLI-пайплайн и построение обучающего CSV в рабочем прогоне удалены.
SIMALIGN_MODEL/DEVICE/LAYER/METHOD больше не задают настройки рабочего пайплайна:
используйте общую конфигурацию. Другие окружения внешних инструментов сохраняются.

## Vecalign, LASER и ошибка «No module named vecalign»

Этап `overlap` — обработка текста, поэтому по умолчанию выполняется внутри
приложения без импорта или установки Vecalign. Результат совместим с upstream:
уникальные отсортированные комбинации соседних строк, `PAD`, `BLANK_LINE`,
ограничение 10000 символов на комбинацию. Вход читается как UTF-8 с поддержкой BOM.
Ошибка входа не перезаписывает прежний результат.

Сам этап `align` требует рабочего Vecalign; `embed` — `laser_encoders`.
Установка COMET в `.venv-comet12` не устанавливает эти зависимости в `.venv`.
Путь к Python в строке `Executing:` показывает, какое окружение действительно
используется. Совместимость ML-зависимостей с Python 3.15 не гарантирована:
выберите подготовленное совместимое окружение (например, Python 3.12 или WSL).

На странице **«Настройки → Внешние инструменты: Vecalign и LASER»** сохраните
пути к окружениям и нажмите проверку доступности. Она вызывает Vecalign с `--help`
(включая импорт его зависимостей), а для LASER проверяет импорт `laser_encoders`.
Модели и готовность CUDA этой проверкой не проверяются. Те же проверки выполняются
перед соответствующим этапом, с диагностикой выбранного интерпретатора.

Пример раздела общего JSON для Windows (пути замените на существующие):

```json
{
  "external_tools": {
    "backend": "native",
    "vecalign_python": "D:\\piton\\.venv-align\\Scripts\\python.exe",
    "laser_python": "D:\\piton\\.venv-laser\\Scripts\\python.exe"
  }
}
```

Для WSL выберите `backend: "wsl"`, укажите `wsl_project_dir` (например,
`/mnt/d/piton`) и Linux-пути к Python. Для исходников без установленного пакета
задайте `vecalign_script`: путь к `vecalign.py` в выбранной ОС.
LASER вызывается через `-m src.processing.alignment.embeddings` из каталога проекта.

Непустые значения JSON имеют приоритет над переменными `EXTERNAL_TOOLS_BACKEND`,
`VECALIGN_PYTHON`, `LASER_PYTHON`, `WSL_PROJECT_DIR`, `VECALIGN_SCRIPT`,
`VECALIGN_OVERLAP_SCRIPT`. Пустые поля сохраняют прежнее поведение переменных
окружения; без них используется native и Python приложения (в WSL — python3).
`overlap_script`/`VECALIGN_OVERLAP_SCRIPT` позволяют явно выбрать внешний overlap.py;
чтобы использовать встроенный генератор, оставьте поле пустым и удалите эту переменную.

После изменения размера групп пересоздайте overlaps и LASER вместе: строки
overlaps должны соответствовать строкам файла эмбеддингов. Затем повторите `align`
и зависимые этапы.

## Карта слов

Результат `word_alignment.token_map` содержит ID/текст/предложение каждого токена,
принятые соответствия, три лучших альтернативы с cosine similarity и статус.
`no_reliable_match` означает отсутствие принятой связи; `sentence_unaligned` —
пустую сторону предложения; `not_processed` — невыполненное выравнивание.
Связи проходят фильтр минимального косинусного сходства (0.55) и отрыва от
альтернатив хотя бы в одном направлении (0.02). Пороги экспериментальные,
их следует калибровать на размеченной выборке; similarity не является вероятностью.
Все методы сохраняются, поддерживаются связи один-ко-многим и многие-к-одному
для стратегий, которые их предлагают. Одна матрица извлекается из того же прохода
SimAlign, повторного вычисления эмбеддингов нет.

`coverage` содержит направленное покрытие лексических токенов, взвешенный сходством
показатель и консервативный минимум покрытий сторон. Они помогают оценивать полноту
предполагаемых соответствий, но не доказывают смысловую эквивалентность: служебное
слово может быть выражено грамматически, а сильная связь может соединить разные смыслы.
Вычисленные связи, отклонённые как ненадёжные, не используются кандидатами.
Пустая группа не создаёт дополнительную ложную тревогу о сбое SimAlign.
Подтверждённое отсутствие описания в Glenny остаётся реальным расхождением входов.

После изменения размера Vecalign пересоздайте overlaps, LASER, alignment и зависимые
этапы. После изменения порогов/метода слов пересоздайте word_align, candidates,
corpus и MQM. Старые файлы доступны для просмотра, но новых карт и оценок в них нет.

## Выбранный кандидат

Кнопка на странице кандидатов оценивает ровно выбранное окно с его сигналами.
Она учитывает fixed/adaptive режим открытого отчёта и сохраняет результат в
`<пара>.mqm[.adaptive].selected-<номер>.json`, не перезаписывая общий отчёт.
Тот же режим доступен из CLI. Полный и точечный запуск используют одни настройки модели.
