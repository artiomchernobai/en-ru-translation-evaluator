# COMETKiwi: оценка окон выравнивания

В фиксированном режиме каждая запись Vecalign становится центром окна:
предыдущая группа + центр + следующая группа. Адаптивный режим описан ниже. Это группы, а не фиксированное число предложений. На краях
документа окно сокращается. Для каждой стороны предложения соединяются пробелом
в исходном порядке. Используется `normalized_text` из нормализованных JSON.

Модель оценивает **всё окно**, не только центральную запись. Балл выше обычно
означает лучшее качество, но не является вероятностью правильности. Текстового
объяснения ошибки стандартный COMETKiwi не возвращает; MQM-анализ выполняется
отдельно. Перекрывающиеся окна не являются независимыми наблюдениями: среднее
их баллов не следует выдавать за стандартную оценку COMET всего документа.

## Установка и модель

COMETKiwi и Streamlit 1.67 требуют несовместимые версии protobuf. Установите
COMET в отдельное окружение **Python 3.12**, не добавляя туда Streamlit:

```powershell
py -3.12 -m venv .venv-comet12
.\.venv-comet12\Scripts\python.exe -m pip install --upgrade pip
.\.venv-comet12\Scripts\python.exe -m pip install -r src/processing/evaluation/requirements.txt
.\.venv-comet12\Scripts\python.exe -m pip check
```

Интерфейс продолжайте запускать из прежнего окружения приложения. На странице
«Оценка перевода» → «Модель и параметры запуска» задайте путь к Python COMET:
`D:\piton\.venv-comet12\Scripts\python.exe`, сохраните настройки.
Этап запускает отдельный процесс в этом окружении; журнал и JSON остаются общими.
Все выбранные переводы обрабатываются одной загрузкой модели.

Вместо поля UI можно перед запуском приложения задать переменную PowerShell:

```powershell
$env:COMETKIWI_PYTHON = "D:\piton\.venv-comet12\Scripts\python.exe"
```

Без отдельного интерпретатора используется текущий Python. В совместимом
окружении без Streamlit достаточно:

```powershell
python -m pip install -r src/processing/evaluation/requirements.txt
```

По умолчанию используется `Unbabel/wmt22-cometkiwi-da`, CPU, батч 8. Модель
загружается один раз на задачу, затем используется для всех выбранных переводов.
Первая загрузка получает checkpoint; следующие используют кэш библиотеки.
Проверьте условия доступа/лицензию выбранной модели на Hugging Face. При
необходимости авторизуйтесь локально через `hf auth login` после принятия условий.
Токены не записываются в JSON результатов или настройки приложения.

На странице «Оценка перевода» можно сохранить имя модели либо путь к уже
скачанному COMETKiwi `.ckpt`, размер батча выбор GPU и путь к Python отдельного окружения. Настройки находятся в
`data/cometkiwi_settings.json`; они применяются к следующему запуску UI и main.
Если настройки отсутствуют, модель можно задать переменной `COMETKIWI_MODEL`.
Нужна именно модель QE/COMETKiwi, работающая без эталонного `ref`.

## Запуск

Отдельный этап на существующих нормализованных предложениях и `.align`:

```powershell
python -m src.processing.main --stage cometkiwi
python src/processing/main.py --stage cometkiwi
```

Этап также включён в полный пайплайн после выравнивания слов. Сам COMETKiwi
не использует результаты SimAlign, поэтому его можно запускать отдельно сразу
после Vecalign. В UI есть кнопка этапа и страница просмотра результатов.

Произвольные имена файлов, без реестра документов приложения:

```powershell
.\.venv-comet12\Scripts\python.exe -m src.processing.evaluation.io --source data/normalized/book-ru.json --target data/normalized/book-en.json --alignment data/aligned/book.align --output data/translation_quality/book.cometkiwi.json --model Unbabel/wmt22-cometkiwi-da --batch-size 8 --gpus 0 --radius 1
```

Для внедрения уже загруженной модели:

```python
from src.processing.evaluation.cometkiwi import CometKiwiBackend
from src.processing.evaluation.io import evaluate_files

backend = CometKiwiBackend(preloaded_model, model_name="my-cometkiwi")
evaluate_files(source_path, target_path, alignment_path, output_path, backend=backend)
```

`build_windows` и `evaluate_windows` не читают и не записывают файлы. Их можно
использовать напрямую с документами и внедрённым адаптером модели.

## Результат

По умолчанию создаётся один файл на пару:
`data/translation_quality/original-rus_<перевод>.cometkiwi.json`.

- `model`: модель, checkpoint, параметры, направление и область оценки.
- `inputs`: пути и SHA-256 входных файлов, плюс время создания результата.
- `windows`: центр, номера соседних групп, индексы/идентификаторы/тексты
  предложений обеих сторон, точные исходные строки Vecalign и их стоимости.
- `verdict`: `status`, `score`, `scope: entire_window`.
- `summary`: количество окон каждого статуса.

Статусы: `scored`, `empty_side`, `too_long`. При пустой стороне всего окна модель
не вызывается. Пропуск внутри непустого окна сохраняется в составе и отмечается
`alignment_gap_present`; оценка не отменяет необходимость проверки пропуска.
Длинные окна отмечаются `too_long` с количеством токенов, без незаметного
обрезания. Входное выравнивание обязано полностью и монотонно покрывать документы.
Результат записывается атомарно после успешной обработки, входы не перезаписываются.

Окна пересекают границы абзацев/глав, если такие границы не представлены отдельным
ограничением входного выравнивания: автоматическое распознавание глав не выполняется.

## Фиксированная и адаптивная сборка контекста

В UI «Модель и параметры запуска» можно выбрать `fixed` (прежнее окно из трёх
групп) или `adaptive`, верхний предел токенов и число дополнительных групп.
Изолированный Python COMET использует те же сохранённые параметры. По умолчанию
сохраняется фиксированный режим.

Адаптивный режим начинается с предыдущей, центральной и следующей групп (на
границах документа — с имеющихся). По признакам продолжения, слов автора,
незавершённого окончания, непарных кавычек и короткого ответа без вопроса в
контексте он добавляет соседнюю группу слева или справа. При необходимости обеих
сторон направления чередуются. После каждого добавления признаки пересчитываются.
Это детерминированные RU/EN-эвристики; они не гарантируют идеальных смысловых границ.
Автоматического распознавания глав по-прежнему нет.

Каждая попытка расширения токенизируется **тем же токенизатором, которым пользуется
загруженная модель**, со специальными токенами, без truncation. Лимит проверяется
отдельно для русского и английского текстов; применяется меньший из пользовательского
предела и пределов модели/токенизатора. По умолчанию дополнительно разрешено 6 групп.
Соседняя группа добавляется целиком. Если исходные три группы уже не помещаются,
они сохраняются с `minimum_exceeds_token_limit`, не расширяются, а COMET отмечает
`too_long`. Из окна не удаляются предложения и не обрезается текст.

В JSON сохраняются `window_config`, а для каждого адаптивного окна — `context`:
исходная тройка, направления/причины принятых расширений, фактические числа токенов,
лимит и причины остановки. Оценка по-прежнему относится ко всему окну.

Результаты режимов могут существовать одновременно:

```text
<пара>.cometkiwi.json           фиксированная сборка
<пара>.cometkiwi.adaptive.json  адаптивная сборка
```

Для отдельного CLI:

```powershell
.\.venv-comet12\Scripts\python.exe -m src.processing.evaluation.io --source data/normalized/book-ru.json --target data/normalized/book-en.json --alignment data/aligned/book.align --output data/translation_quality/book.cometkiwi.adaptive.json --window-strategy adaptive --max-extra-groups 6 --max-tokens 510
```

Адаптивный режим требует `radius=1`. Фиксированный CLI сохраняет прежнюю поддержку
других радиусов. Старые JSON без `window_config` продолжают читаться как фиксированные.

На страницах оценки и кандидатов добавлены кнопки «Предыдущий фрагмент» и
«Следующий фрагмент» над сравнением текстов. Они синхронизированы с существующим
списком. Индикатор показывает позицию и номер группы; для COMET — оценку окна,
для кандидатов — приоритет. Крайние кнопки блокируются. При сортировке/фильтрации
сохраняется текущая группа, если она остаётся в списке; смена файла сбрасывает выбор.
